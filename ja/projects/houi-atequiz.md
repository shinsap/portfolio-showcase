# 方位当てクイズ

## 目的・位置付け

地理クイズのデータからショート動画とカバー画像を制作する、ローカルの動画作成テストです。[TikTok @houiatejp](https://www.tiktok.com/@houiatejp)で公開しています。GitHubリポジトリはなく、ホスティングされたアプリではなくメディア処理の技術実験として紹介します。

## 制作フローと設計

1. 正解地点と基準5地点のJSONを読み込みます。方位・距離は上流で計算済みの値を使います。
2. 同梱のMapLibre GL 4.7.1とOpenFreeMap Positronで地図を描画し、HTML・SVGを重ねます。距離は対数スケールで表示し、近距離と遠距離の基準点を同時に読めるようにします。
3. ローカルのVOICEVOXでナレーションを作り、音声長に合わせてタイムラインを構成。NumPy・SciPyで固定シードのBGM・効果音を生成し、画面のイベント時刻に合わせます。
4. PythonからPlaywright・Chromiumを操作し、各フレームの`renderAt(time)`で描画。スクリーンショットをFFmpegの`image2pipe`へ送り、1080×1920・30fps・約21秒のH.264動画へ変換します。
5. ブラウザ描画からカバー画像も作り、文字数とTikTokのセーフエリアに合わせて配置します。

フレーム単位の時刻制御は場面のタイミングを再現するためのもので、動画ファイルがバイト単位で同一になる保証ではありません。地図タイルは外部依存です。

## 途中の課題と修正

基準地点が同じ方向へ集中すると読みにくくなるため、平均方向ベクトルを使って中心を反対側へずらし、ラベルの接線方向の調整も行っています。PythonとJavaScriptで位置計算の式をそろえました。

駅名や出力名の固定処理をデータに応じた処理へ変更し、カバーの文字切れ、末尾区間の重複、ラベルの収まりを修正しました。音声も独立した固定時刻表ではなく、画面のイベント時刻と連動させています。

地名専用の読み辞書は未整備で、すべての地名を正しく読み上げる保証はありません。地図側に表示されない駅名もあります。

## 担当・検証範囲

自分は動画の企画、見せ方の要件、制作テストの受け入れを担当し、開発にAIを活用しています。技術情報は2026-11-08のコード・文書確認に基づきます。今回のポートフォリオ更新で動画の再生成やメディア検査を実施したものではなく、視聴維持率の改善実績も主張しません。

**技術：** Python / Playwright / Chromium / HTML・SVG / MapLibre GL / OpenFreeMap / FFmpeg / VOICEVOX / NumPy / SciPy。
