# Vulneramigo（ヴァルネラミーゴ）

## 概要

Vulneramigoは、Webサイトのセキュリティ設定と、PHP・Node.js・Oracle Javaの脆弱性情報を、Web制作会社とそのお客様の双方が理解できるレポートに整理する軽量なWebアプリ（PWA）です。セキュリティの専門家ではない方でも、何を改善すべきか、次に何をすればよいかを把握できるよう、顧客とのコミュニケーションに役立つツールとして設計しています。

現在は公開済みで、https://vulneramigo.nortelia.co.jp/ で利用できます。

## 課題 → 解決

**課題：** サーバー側の技術に関する脆弱性情報は専門的な言葉で公開されています。Web制作会社はPHP・Node.js・Javaの更新がなぜ必要かをお客様に説明する場面が多く、中小企業のWebサイト担当者にとっては、その情報が自社に関係するのか、どの程度急ぐべきかを判断するのが難しい状況です。

**解決：** 次の2つの診断を、単独でも組み合わせても使え、1つのレポートにまとめられます。

- **URL診断（非侵入型）：** 調べたいWebサイトのURLを入力すると、公開されているセキュリティ設定を確認します。HTTPS接続とHTTPからHTTPSへのリダイレクト、セキュリティヘッダー（CSP・HSTS・X-Content-Type-Options・X-Frame-Options・Referrer-Policy・Permissions-Policy）、メール・DNS設定（SPF・DMARC・MX・CAA）が対象です。結果は「確認できた項目」「改善を推奨する項目」「確認できなかった項目」に分け、説明文と改善のヒントを添えて表示します。
- **バージョン診断（CVE）：** PHP・Node.js・Oracle Java SEを選んでバージョンを入力すると、ツールに収録済みの脆弱性情報（公式情報に基づくもの）と照合し、関連するCVE、更新の必要性、公式情報の参照先を表示します。

範囲はレポート上にも明記しています。URL診断は非侵入型の簡易診断で、Webサイト全体の安全性を保証するものではありません。バージョン診断の対象は、収録済みの情報と利用者が入力したバージョンに限られ、URLからPHPやNode.jsのバージョンを自動特定することはありません。サイト内部の脆弱性の自動発見も行いません。判断に必要な情報が足りない場合は「安全」と表示せず、判定できないことをそのまま伝えます。

**対象ユーザー：** お客様のWebサイトを保守しているWeb制作会社、中小企業のWebサイト担当者。

## 主な機能

- URLによるセキュリティ設定診断（HTTPS・セキュリティヘッダー・SPF/DMARC・MX/CAA）と、確認できた／改善推奨／確認できなかったの3区分の結果表示
- PHP・Node.js・Oracle Java SEのバージョン別CVE診断（URL診断と単独でも組み合わせても利用可能）
- URL診断の結果を統合した詳細PDFレポート（診断対象サイトと日時、確認結果、改善ヒント、ソフトウェアの脆弱性情報、診断範囲と注意事項）。URL診断のみの場合も表紙に対象ドメインを表示
- 任意のPDF付録「アクセスしたあなたの環境から分かること」（3ページ）：Webサイトへのアクセス時にブラウザや端末から取得できる情報を、「観測値」「推定」「取得不可」に区別して紹介し、複数の情報の組み合わせで識別され得ることも解説。利用者が選択した場合のみブラウザ内で取得し、外部送信・永続保存・追跡用ID／フィンガープリントのハッシュ生成は行わず、IPアドレス・正確な位置情報・カメラやマイクは取得しない
- URL入力を中心にしたトップページへ刷新し、バージョン診断は技術者・Web制作者向けの折りたたみ領域へ移動
- PHP・Node.js・Oracle Java SE・CISA KEV・OSV.devの確認状況を公開する監視パネル（Phase 1：手動更新、自動更新は未実装）
- 日本語・英語・スペイン語の画面とレポート
- Webサイト担当者向けの平易なまとめと、同じレポート内の制作会社向け技術情報
- 推奨される対応と公式情報へのリンク

## 担当範囲

- プロダクト企画、顧客コミュニケーション支援ツールとしての位置づけ整理
- 要件定義（レポートが示すこと・示さないことの範囲と表現を含む）
- 担当者向け・制作会社向けの2種類の読み手を想定したレポートと画面フローの設計
- 多言語コンテンツ設計（日本語 / 英語 / スペイン語）
- 非侵入型URL診断の設計・実装（確認できた／改善推奨／確認できなかったの3区分）
- ブラウザ中心のPWAの実装
- 公式情報に基づく収録データの整備

## 技術スタック

## 伝えられること

- 専門的な技術情報を、顧客とのコミュニケーションに使える成果物へ落とし込む設計
- 非技術者の意思決定者と技術者という、2種類の読み手を同時に想定した設計
- ツールの対象範囲を明確にし、断定しすぎない表現の設計
- プライバシーに配慮した設計（任意のアクセス環境付録は選択時のみブラウザ内で取得し、送信・永続保存・フィンガープリント生成を行わない）
- 「観測値」「推定」「取得不可」を区別し、言えること・断定できないことを明確にする表現設計
- 国内外の利用者を想定した多言語プロダクト設計
