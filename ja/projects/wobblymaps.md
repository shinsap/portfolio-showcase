# WobblyMaps

## 目的・位置付け

地図の輪郭を転がす映像を、地理データから生成するローカルの動画作成テストです。[TikTok @wobblymaps](https://www.tiktok.com/@wobblymaps)で公開しています。GitHubリポジトリはなく、データから映像を作る処理と見せ方の実験として紹介します。

## 制作フロー

1. GeoJSONから最大の外周を抽出し、緯度補正、Douglas–Peuckerによる簡略化、最大幅100への正規化を行います。ランドマークにも同じ座標変換を適用します。
2. Canvas 2Dで接地点となる頂点を順に切り替えて転がりを表現します。厳密な物理シミュレーションではありません。
3. Python・PlaywrightがJavaScriptの状態を持つ`exportStep`を固定刻みで進め、フレームを撮影してFFmpegへ送ります。
4. JavaScriptの接地点切り替えとサブステップを読み取り、NumPyで接地音を生成します。画面と音で別々の接地判定を実装しない構成です。macOSの`say`による短い音声は任意です。
5. 動画と、別途1080角のカバー画像を出力します。

現行v3のTikTok動画は**1200×710**で、タイトル3秒・転がり7.5秒・終了画面1.5秒の計12秒です。旧版の9:16構成とは区別します。X向けも1200×710で、こちらは無音です。

## 変更・修正と制約

raqmなしのPillowでは旗の絵文字を意図どおり描けなかったため、タイトルをChromiumで画像化する方式へ変更しました。

技術メモでは冒頭1〜3秒の離脱を理由に、ズームの廃止とタイトル表示の3秒化を行っています。ただし、その変更後に視聴維持率が改善した測定結果は確認していません。

最大外周を使うため、別の島や穴は省略します。地理的な形状と転がりを単純化した表現です。また、旧エクスポーターを呼ぶラッパーが残っており、制作経路が完全に統一された完成品とは位置付けていません。

## 担当・確認根拠

自分は企画、見た目の要件、制作テストの受け入れを担当し、実装にAIを活用しています。技術情報は2026-11-08のコード・文書確認に基づき、今回の動画再生成や新しい性能測定の結果ではありません。別管理の運用ノートはこの確認の対象外です。

**技術：** Python / GeoJSON / JavaScript / Canvas 2D / Playwright / Chromium / FFmpeg / NumPy / Pillow。
